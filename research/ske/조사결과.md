# SKE 공용리모컨 조사결과

분석 기준: 2026-11-07. 대상 앱의 정적 구현을 확인한 결과이며, 현장 음향신호기의 펌웨어나 실제 동작을 검증한 결과가 아니다.

## 대상 및 무결성

패키지 `kr.sktechnology.remote`, 버전 `1.5`, versionCode `6`. Google Play 설치본을 사용자가 ADB로 추출했다. 원본은 수정하지 않았다.

| 파일 | SHA-256 |

| base.apk | `709fca0f26ca6004dbae975a899b61a0ca974d3209456548b3921ceb55aed327` |
| split_config.ko.apk | `8bd044789bff80243a044e05690a134c1b6cffa124402593d1ffccd2522b59bc` |
| split_config.xxhdpi.apk | `8c50249534e3f31c7b6ba603510bb2a7488b47fba7543007207e7207b0c7a663` |

기준 목록과 재대조했다. 제공된 split 2개에는 DEX·네이티브 라이브러리가 없고 base에 `classes.dex` 1개가 있다. 공급된 파일 구성에 관한 결과이며 기기 설치 목록 전체와의 재대조는 별도다. 구조화 증거: [apk_identity.json](evidence/apk_identity.json).

## 확인된 구현

| 단계 | 코드 근거 | 결과 |
| --- | --- | --- |
| 문자열 복원 | `LL0;->a([I)`, `<clinit>` `code_off=348960` | 정수 배열을 `0x5A` XOR하여 접두어 2개·UUID 4개 복원, `UUID.fromString()`으로 초기화 |
| 스캔 | `r3.j`, `q3.onScanResult` `code_off=956940`, `o3.run` | 필터 인자 null의 LOW_LATENCY 스캔 후 이름·RSSI를 앱에서 검사 |
| 연결 | `r3.i`, `n3.onConnectionStateChange`, `k3.run` | LE GATT 연결, 서비스 탐색, cdd0 서비스/cdd1 Notify/cdd2 Write 조회 |
| 송신 | `r3.o(K0)` `code_off=973468`, `K0` | 위치안내·신호안내·음성안내 요청을 Characteristic 쓰기로 전송 |
| 수신 | `n3.onCharacteristicChanged` `code_off=925632`, `m3.run` `code_off=917584` | 메인 GATT와 Notify UUID 검사 후 안내 명령 ACK 결과를 UI에 반영 |
| 자동 동작 | `MainActivity.q0`, `j1`, `cb.run`, `E2.run`, `i3.run(case 8)` | 자동 안내 기본값 true 및 보조 연결 후 쓰기 경로 존재 |

스캔은 `AHG001+` 또는 `BHG001+` 접두어를 사용한다. 광고 이름이 없으면 기기 이름으로 대체한다. 최초 관측 기본 임계값은 -85 dBm이며 설정 가능하다. 이후 RSSI는 이전 0.7·새 값 0.3 가중평균이다. MAC 중복 제거와 기기 유형 분류를 사용하지만, 공개 증거에는 실장비 MAC을 포함하지 않았다.

기존 JADX 선택 내보내기 기준 `q3.java:26–69`, `o3.java:35–89`, `r3.java:615–626`, `n3.java:27–111`, `k3.java:29–94`를 DEX 위치와 대조했다. 디컴파일러 버전에 따라 Java 행 번호·이름은 달라질 수 있으므로 DEX 위치와 SHA-256을 우선한다. 원문 전체는 공개하지 않는다.

## 실시간 보행신호 수신 여부

정의된 DEX 메서드 **7,748개**의 직접 참조 감사에서 `readCharacteristic`, `readDescriptor`, `readRemoteRssi` 호출은 0건이다. `getValue`는 Notify 콜백 1건이며 `onCharacteristicRead` 오버라이드는 없다. 광고 Manufacturer Data·Service Data·Service UUID·raw bytes를 가져오는 직접 호출도 없다. 명시적 페어링 API 호출은 발견되지 않았으나 OS 자동 페어링 부재까지 입증하지는 않는다.

`I0(AhgResponse)` 외부 소비는 `m3.run()`의 생성과 `isAck` 조회다. `raw`·`deviceSpecInfo`를 읽어 보행 현시·잔여시간으로 변환하는 별도 직접 소비자는 발견되지 않았다. '보행 신호 상태 안내'는 `MainActivity.H0/L0`의 버튼 설명이고 '신호 강함/보통/약함'은 RSSI 표시다. 화면의 음향신호기 순번은 `MainActivity.Z(int)`가 발견 목록에서 계산하며 물리 교차로 ID가 아니다.

**판정:** 분석한 APK에서 적·녹색, 잔여시간, 교차로·횡단 방향을 구조화하여 수신·처리하는 구현은 **미발견**이다. 확인된 음향안내 명령 ACK와 실시간 보행신호 데이터는 구별한다. **장치 자체의 미지원 확정이나 읽기 전용 수신 불가능의 증명은 아니다.** 장치 속성·규격·허가된 격리 시험의 수동 수신 자료가 필요하다.

증거: [receive_path_audit.json](evidence/receive_path_audit.json), [passive_ble_audit.json](evidence/passive_ble_audit.json), [state_indicator_audit.json](evidence/state_indicator_audit.json), [auto_guidance_audit.json](evidence/auto_guidance_audit.json). 직접 참조 감사는 반사 호출 등 모든 런타임 동작을 증명하지 않는다.

## 웹앱·T-DATA와의 관계

`observer.html`의 이름·UUID는 이 APK와 일치한다. Android 앱의 RSSI 선택·자동 안내 동작을 복제하지 않으며, 수동 Read/Notify 원시 수신만 기록한다. Notify 구독은 CCCD 쓰기를 동반할 수 있다. 공식 앱은 자동 안내 Characteristic 쓰기가 가능하므로 수신 전용 관측 도구로 가정하지 않는다.

T-DATA 10121/10381은 별도 HTTP 정보원이다. API의 방향·교차로 필드를 BLE 이름이나 발견 목록 순번에 대응시키는 근거는 없다. 인증키 없는 모의 테스트를 실제 API 성공으로 해석하지 않는다. 공공 장치에 연결하거나 제어·설정·안내 요청을 전송한 사실은 없다.
