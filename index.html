WEB BLE SCAN · v0.6

보행신호기 BLE 탐지

경찰청 음향신호기 BLE 규격 및 SKE 앱의 AHG001+·BHG001+ 식별 규칙과 UART Service UUID를 활용한 연구용 페이지입니다. 사용자 동의 시 GATT 서비스·Characteristic을 조회하며, 신호기 작동 명령이나 쓰기 기능은 없습니다. R03 실기기 호환 여부는 미검증입니다.

새 실험: BLE Notify 수신 패킷 실험실(v0.3) 열기 — 원시 데이터 기록과 적·녹색 관찰 시점 표시. 장치와 실제 프로토콜 검증은 별도입니다.
T-DATA 실측 대시보드: 신호정보 관측 웹앱 열기 — 경찰병원후문 두 교차로의 실측 이력과 원본 상태 필드를 확인합니다. 실시간 조회는 로컬 프록시 실행 시에만 가능합니다.
⚠️ 횡단 안전 판단용이 아닙니다. 검색에 성공해도 해당 장치의 설치 위치, 신호 상태, 적색·녹색 여부는 확인되지 않습니다. 도로에서는 안전한 인도에서만 사용하세요.

01 · 탐지 설정

SKE APK에서 확인된 두 접두어를 모두 검색합니다. 현장 기기의 실제 이름은 미확인입니다. 검색 실패 시 이름 조건 없는 전체 기기 선택을 사용하세요.
실험적 연속 스캔 결과를 화면에서 걸러주는 표시 기준이며, 실제 거리나 브라우저 스캔 범위를 제한하지 않습니다.
브라우저 상태 확인 중
모드 차이와 브라우저 설정

기본: Chrome의 장치 선택 창에서 AHG001+ 또는 BHG001+ 이름의 장치를 확인. 장치를 선택해도 GATT에 연결하지 않음. 기기명은 브라우저가 광고에서 받은 정보이며, 광고 원본·RSSI는 볼 수 없음.

실험: requestLEScan() 지원 시 광고 데이터·RSSI·제조사/서비스 데이터를 연속 표시. Android Chrome에서 chrome://flags/#enable-experimental-web-platform-features를 켜고 브라우저를 다시 실행해야 할 수 있으며 지원이 보장되지 않음. 버튼이 비활성화되면 기본 장치 선택으로 진행하세요.

선택 장치 관찰: watchAdvertisements() 지원 시 선택한 장치의 광고를 관찰. 지원하지 않는 브라우저는 동작하지 않음.

Web Bluetooth 사용에는 HTTPS 또는 localhost 환경 및 사용자의 직접적인 클릭이 필요합니다. HCI 원시 패킷, 전체 주변 기기의 주소/목록은 브라우저에서 얻을 수 없습니다. 일반 스캔 자체가 장치 제어 명령을 보내지는 않지만, BLE Scan Request 등의 무선 패킷은 발생할 수 있습니다. 웹 스캔 가이드

⚠️ GATT 연결은 수동 스캔과 달리 기기와 실제 통신합니다. 사용 권한이 있는 실험 장치에서만 실행하세요. 연결에 실패해도 BLE 모듈 부재를 단정할 수 없습니다.

04 · 세션 기록

데이터는 서버에 자동 업로드되지 않고 이 탭의 메모리에만 보관됩니다. JSON 공유 시 기기 식별자 등 개인정보를 확인하세요.
범위: BLE 광고 탐지, 사용자가 선택한 장치의 GATT 서비스·Characteristic 조회 및 읽기 가능 값의 수동 읽기. 쓰기·제어 요청·Notify 등록 기능은 없음.
R03 공지: 경찰청 2026-02-20 표준규격 공지 · 근거: 경찰청 R01 표준규격 (2024, 25쪽) · SafeLight 개발 문서 · MDN requestDevice.
제한: 이 버전은 실시간 보행신호 상태·잔여시간을 해석하지 않습니다. R03 규격과 현장 장비의 실제 호환 여부는 확인되지 않았습니다.
